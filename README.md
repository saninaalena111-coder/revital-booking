# Онлайн-запись Ревиталь Парк — прототип

Кликабельный презентационный прототип собственной системы онлайн-записи Ревиталь Парк.
Все врачи, пациенты, кабинеты и расписание вымышлены. Реального API МИС «Санаториум» и отправки СМС нет.

## Фирменный стиль

Шрифт — Myriad Pro (Adobe, лицензионный). Файлы шрифта лежат в `src/fonts/` только локально
и не публикуются в репозитории (см. `.gitignore`). Для сборки на другом компьютере положите туда
`MyriadPro-Light.otf`, `MyriadPro-Regular.otf`, `MyriadPro-SemiBold.otf`, `MyriadPro-Bold.otf`.
Логотипы — `src/assets/brand/`.

## Запуск

```bash
npm install
npm run dev      # http://localhost:3000
npm run build    # production-сборка (все страницы статические)
```

## Экраны

| Путь | Что показывает |
|---|---|
| `/` | Главная: hero, преимущества, каналы-источники (ссылки с UTM), три пути пациента, врачи |
| `/booking` | Пошаговая запись: гость санатория / будущий гость / амбулаторный пациент |
| `/logic` | Как система принимает решение о доступном времени: 4 примера + песочница, правило основного кабинета |
| `/how-it-works` | Архитектура, API, webhook vs периодическая синхронизация, разделение данных, этап 2 |
| `/requirements` | Что потребуется от МИС — простой экран для руководства |
| `/cabinet` | Личный кабинет: записи (перенос/отмена), назначения (этап 2), СМС-уведомления |
| `/admin` | Дашборд для сотрудников: календарь, врачи, кабинеты, источники, СМС, интеграция + раздел «Для разработчиков» (обмен данными, события, структура данных, алгоритм, устройство прототипа) |

Кнопка «Демо-сценарии» (справа внизу) ведёт по семи вопросам презентации и сбрасывает демо-данные.

Демо-«сегодня» — понедельник, **12 октября 2026**. На этот день вручную расписаны все примеры из ТЗ.

## Архитектура

```
src/
  lib/
    types.ts               доменные типы — контракт между UI и сервисами
    scheduling/engine.ts   движок доступности: врач + услуга + смена + кабинет + занятость
    rules.ts               бизнес-правила (гостю — только первичный терапевт)
  services/                слой данных — UI импортирует только отсюда
    doctorsService         врачи, смены, услуги, направления
    appointmentsService    слоты, создание, перенос, отмена
    roomsService           кабинеты, режимы доступа, занятость
    patientsService        идентификация гостя
    integrationService     шлюз к МИС: контракт API, события, этап 2
    notificationsService   СМС-шаблоны и цепочки напоминаний
    analyticsService       показатели и источники записей (UTM)
  mock/                    вымышленные данные и in-memory «база» демо-режима
  components/              интерфейс (не знает о mock-данных)
```

### Как подключить реальную МИС

1. Реализовать HTTP-клиент к API «Санаториума» на серверной стороне (ключи не во frontend).
2. В `src/services/*` заменить обращения к `@/mock/*` на вызовы `integrationService` — места помечены комментариями `РЕАЛЬНЫЙ API`.
3. Добавить приём webhook (`POST /api/integrations/sanatorium/events`) и резервную периодическую синхронизацию.
4. Переключить `NEXT_PUBLIC_DATA_SOURCE=mis` (см. `src/services/config.ts`).

Компоненты интерфейса при этом не меняются: они работают только с методами сервисов и типами из `lib/types.ts`.
