# Ревиталь — онлайн-запись и МИС сети санаториев (прототип)

Кликабельный презентационный прототип для руководства сети санаториев «Ревиталь».
Один продукт с двумя сторонами на общих демо-данных:

- **Сторона гостя** — сайт с онлайн-записью и личный кабинет: расписание процедур, курс
  «назначено / пройдено», заказ питания, документы, проживание.
- **Сторона персонала (МИС)** — медицинская информационная система для 4 санаториев,
  которая заменяет коробочную МИС «Санаториум»: приём врача с голосовым вводом, назначения
  с автораскладкой, процедурный кабинет, ЕГИСЗ, размещение, питание, аналитика, администрирование.

Все люди, телефоны, документы, цены и загрузка вымышлены. Бэкенда, ключей API и внешних
запросов нет — сайт полностью статический.

## Запуск

```bash
npm install
npm run dev      # http://localhost:3000
npm run build    # статическая сборка в out/
npm run lint
npm run deploy   # сборка с PAGES_BASE_PATH=/revital-booking и публикация в ветку gh-pages
```

Опубликованная версия: https://saninaalena111-coder.github.io/revital-booking/

### Фирменный шрифт

Myriad Pro (Adobe) лицензионный: файлы лежат в `src/fonts/` только локально и не попадают
в репозиторий (`.gitignore`). Перед `dev`, `build`, `lint` и `deploy` запускается
`scripts/prepare-fonts.mjs`: если файлов `MyriadPro-Light/Regular/SemiBold/Bold.otf` нет,
сайт собирается на системном шрифте.

## С чего начать показ

1. Откройте главную — блок «Глазами гостя / Глазами сотрудника».
2. Кнопка **«Демо-сценарии»** справа внизу: 9 сценариев МИС по шагам, каждый шаг открывает
   нужный экран под нужной ролью. Там же — «Сбросить демо-данные».
3. Вход в МИС: `/mis` — выбор роли карточками, демо-вход без пароля.

Демо-«сегодня» — понедельник, **12 октября 2026**, демо-«сейчас» — **10:40**.

## Экраны

### Сторона гостя

| Путь | Что показывает |
|---|---|
| `/` | Главная: онлайн-запись, каналы с метками, две стороны продукта |
| `/booking` | Пошаговая запись: гость санатория / будущий гость / амбулаторный пациент |
| `/cabinet` | Личный кабинет: расписание, записи к врачам, назначения, питание, документы, проживание, уведомления |
| `/logic`, `/how-it-works`, `/requirements` | Как система принимает решение о времени, интеграция, требования к МИС |
| `/admin` | Дашборд онлайн-записи и раздел «Для разработчиков» |

### Сторона персонала — МИС (`/mis/*`)

| Путь | Экран | Роли |
|---|---|---|
| `/mis` | Вход и выбор роли | все |
| `/mis/today` | «Мой день» врача | врач |
| `/mis/reception?appointment=…` | Приём: шаблон осмотра, МКБ-10, голосовой ввод, назначения | врач |
| `/mis/patients`, `/mis/patient?id=…` | Гости и карта гостя (приёмы, назначения, расписание, документы, анализы) | врач, медсестра, ресепшн |
| `/mis/procedures` | Процедурный кабинет: очередь, «Выполнено», перенос | медсестра |
| `/mis/rooms-schedule` | Загрузка кабинетов | врач, медсестра |
| `/mis/egisz` | Документы, подпись через QR, отправка в ЕГИСЗ через N3.Health | врач, руководитель |
| `/mis/stays` | Размещение: заезды, выезды, шахматка | ресепшн, бронирование, руководитель |
| `/mis/bookings` | Брони и путёвки, новая бронь | бронирование, ресепшн |
| `/mis/meals` | Питание: сводка для кухни, заказы, диетстолы | ресторан |
| `/mis/booking` | Модуль «Онлайн-запись» внутри МИС | врач, ресепшн, руководитель |
| `/mis/analytics` | Сводная панель по сети | руководитель |
| `/mis/sources` | Источники гостей (метки) | руководитель, маркетолог |
| `/mis/admin` | Пользователи и роли, журнал, вход в два шага, серверы, интеграции | администратор |
| `/mis/help` | Справка «Как…» | все |

Любой экран МИС можно открыть сразу под ролью: `/mis/today?as=doctor`,
`/mis/procedures?as=nurse`, `/mis/analytics?as=manager` и т. д.

## Архитектура

```
UI (components) → services → mock-«база» (src/mock)
```

Интерфейс никогда не импортирует `src/mock` напрямую — только `src/services`. При подключении
реального сервера меняются сервисы (места помечены комментариями `РЕАЛЬНЫЙ API`), экраны — нет.

Подробно: [`CLAUDE.md`](CLAUDE.md) и папка [`docs/`](docs/):

- [`docs/modules.md`](docs/modules.md) — модули МИС и что в них работает;
- [`docs/demo-scenarios.md`](docs/demo-scenarios.md) — сценарии презентации;
- [`docs/demo-data.md`](docs/demo-data.md) — как устроены демо-данные.

### Как подключить реальную МИС

1. Реализовать серверный клиент к API (ключи — только на сервере).
2. В `src/services/*` заменить обращения к `@/mock/*` на вызовы сервера.
3. Добавить приём событий об изменениях и резервную синхронизацию.
4. Переключить `NEXT_PUBLIC_DATA_SOURCE=mis` (см. `src/services/config.ts`).
