# Ревиталь — онлайн-запись и МИС (прототип)

Кликабельный презентационный прототип для руководства сети санаториев «Ревиталь»
(Геленджик, Сочи, Балашиха, 4-й объект уточняется). Смотрят **не технические специалисты**:
человек без подготовки должен понять, куда нажать; всё, чего нет, честно помечено
«В разработке — этап N». Подробности по экранам — `README.md`, по модулям и сценариям — `docs/`.

## Жёсткие правила

- **Только вымышленные люди и данные.** Никаких реальных ФИО, телефонов, паспортов.
- **Без бэкенда, ключей и внешних запросов.** Сайт статический: `output: "export"`,
  публикация `npm run deploy` на GitHub Pages с `PAGES_BASE_PATH=/revital-booking`.
- **Весь интерфейс на русском**, без английских слов для пользователя (кроме названий
  вроде N3.Health, СМС, ЕГИСЗ).
- **UI → services → mock.** Компоненты импортируют только `@/services` (и `@/config`, `@/lib`,
  хуки). Импорт `@/mock/*` из экранов запрещён. Исключения — инфраструктура демо-режима:
  `AppChrome` (`db.hydrate()`), `DemoNavigator` (`db.reset()`), `hooks/useService` (версия данных).
- **Не ломать экраны онлайн-записи** (`/`, `/booking`, `/cabinet`, `/logic`, `/how-it-works`,
  `/requirements`, `/admin`).
- **Шрифт Myriad Pro** лежит в `src/fonts/` только локально; `.gitignore` не трогать.
- **Ни одной кнопки без реакции**: нереализованное — через `ComingSoonButton` /
  `ComingSoonBanner` (`src/components/mis/ComingSoon.tsx`, этапы — `src/config/roadmap.ts`).
- После изменений: `npm run lint` и `npm run build` без ошибок. Коммиты — на русском.

## Next.js 16 — что важно

- Версия с изменениями API: перед новым кодом смотреть `node_modules/next/dist/docs/`.
- **Динамических маршрутов нет** (статический экспорт не построит `/patient/[id]` для данных,
  созданных на показе). Параметры — через query: `/mis/patient?id=…`, `/mis/reception?appointment=…`.
- `useSearchParams` требует `<Suspense>`: для `/mis/*` он уже в `src/app/mis/layout.tsx`.
- Типы `LayoutProps<"/mis">` генерируются при сборке.
- `next build` иногда один раз останавливается сообщением `SecurityFatalError` (предложение
  обновить Next.js) — повторный запуск проходит. Обновление Next — отдельная задача.

## Как запускать

```bash
npm run dev      # http://localhost:3000 (перед запуском готовится модуль шрифта)
npm run build
npm run lint
```

Проверить демо-базу без браузера можно через `jiti` (есть в `node_modules`):
`createJiti(root, { alias: { "@": root + "/src" } })` и импорт `src/mock/mis/generate.ts` →
`datasetSummary()`.

### Демо-данные и состояние

- Генератор (`mock/mis/generate.ts`) строит базу один раз при первом обращении: 100 пациентов
  (70 проживают, 20 будущих, 10 амбулаторных), номерной фонд 4 объектов, назначения и сеансы,
  приёмы, документы, анализы, заказы питания, журнал. Seed фиксирован — без `Math.random`.
- Изменения на показе (новые назначения, отметки, подписи, заселения, брони) хранятся в
  `db.table(name)`: в localStorage попадают только добавленные строки и правки
  (ключ `revital-booking-demo-v2`). `db.reset()` возвращает исходное состояние.
- Сессия МИС — отдельный ключ `revital-mis-session-v1`; сброс демо-данных из системы не выходит.
- Любое изменение вызывает `emit()` → `useService` перезапрашивает данные на всех экранах.
  Поэтому **не логировать в журнал из `useService`** — только из обработчиков или одного
  `useEffect` с защитой `useRef` (иначе бесконечный цикл).
- Записи онлайн-записи (`Appointment`) связаны с пациентами МИС через `patientId`; все записи,
  сделанные в демо на сайте, оформляются на Анну Смирнову (`p-anna`, номер 4-315).

### Связи двух сторон (на этом строится презентация)

- Запись гостя на сайте → `visitsService.doctorDay` показывает её врачу с пометкой «С сайта».
- Назначение врача → `planner.ts` раскладывает сеансы → видны в очереди кабинета и в
  «Моём расписании» гостя.
- Отметка медсестры «Выполнено» → счётчик курса у гостя и в карте.
- Онлайн-запись не предлагает время до `DEMO_NOW` и поверх процедур гостя.

### Роли и вход

- `?as=<role>` в адресе любого экрана МИС сразу входит под ролью (так работают демо-сценарии).
- Руководитель, маркетолог, администратор входят со «Всеми санаториями», остальные — со своим.
- Права: `canOpen(role, section)`; закрытый раздел показывает `NoAccess` и пишет «отказ» в журнал.

### Мультиарендность

Брендинг МИС — из `config/tenant.ts`: цвета подменяют CSS-токены (`brandStyle`) на обёртке
`MisShell`, логотип — `TenantLogo`. Переключатель «Другой санаторий» — в навигаторе демо и
на экране входа.

## Стиль интерфейса

- Токены цветов — `src/app/globals.css` (milk, cream, sand, linen, sage, forest, forest-deep,
  teal, gold, ink, muted, line, danger, ok). Компоненты — `components/ui/*`, `components/mis/ui.tsx`
  (`StatusPill`, `Stat`, `EmptyState`, `useToast`, `card`).
- Статус всегда **цветом и словом**. Кнопки — глаголы («Заселить», «Отметить выполненной»).
- У каждого экрана МИС — `MisTitle` (заголовок + одна строка пояснения) и пустые состояния.
- Крупные кликабельные зоны (≥ 40–44 px), проверка на 375 / 768 / 1366 px.
- Графики — `components/mis/charts.tsx`; категориальная палитра объектов `SERIES_COLORS`
  проверена валидатором (различимость при нарушениях цветового зрения), к графикам — подписи и таблица.

## Известное и неиспользуемое

- `components/integration/Prescriptions.tsx` больше не используется (раньше — заглушка
  назначений в личном кабинете).
- На шаге «Бронирование найдено» онлайн-записи гостю пишется, что процедуры «станут доступны
  после консультации», даже если курс в МИС уже назначен.
- Питание учитывает только гостей с медкартой (70); брони без медкарты в сводку кухни не входят.
- Нагрузка врачей и популярные процедуры в аналитике считаются только по Геленджику.
